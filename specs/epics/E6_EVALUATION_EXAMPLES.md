# E6 — Evaluation and example conversations

## Goal
Prove the agent behaves as specified with a repeatable scenario evaluation, and produce the 3–5
example conversations the challenge requires from **real runs**.

## Why
Non-deterministic systems are tested by **behaviour** (which tool was called, which facts appear),
not exact text. This is the clearest signal of engineering maturity in an AI case.

## Scope
- `eval/scenarios.yaml`, `eval.py` runner, `eval/results.md` (committed).
- `scripts/run_examples.py` → `examples/*.md`.
- Prompt/tool-description tuning loop based on failures (each change = its own commit).

## Check types (per scenario)
- `expect_tools`: tool names that must be called (any order).
- `forbid_tools`: tool names that must not be called.
- `must_contain` / `must_not_contain`: substrings (case/accent-insensitive).
- `numbers_grounded: true`: every number in the reply must appear in the tool results, the user
  messages, or `policies.md` (format-normalised: "2.089,05" ≡ 2089.05).
- `max_turn_seconds`: latency budget (default 20).

## Example conversations (deliverable X6)

Generated by `scripts/run_examples.py` with `EMPORIO_TODAY` fixed; each file shows the dialogue
and, in a collapsible `<details>` block, the tools called with arguments. Light manual curation
(no edits to the agent's words — only choose which runs to keep).

| File | Scenario | Shows |
|---|---|---|
| `01_catalog_search.md` | Violões até R$1000 → follow-up "qual é melhor para iniciante?" | Data query + recommendation from specs |
| `02_price_and_payment.md` | "Quanto custa o Takamine?" → GD20 → PIX and 12x | Clarification + pricing rules (manual §3, §6.2) |
| `03_order_return_escalation.md` | Return request for order 8 → identity check → stale status → escalation | **Non-trivial:** data + policy + privacy + hand-off |
| `04_store_info_out_of_hours.md` | Address, hours, payment methods on a Sunday | Policy answers + dynamic context |
| `05_out_of_scope_and_promos.md` | Cable → redirect → promotions → injection attempt | Scope handling + promotions + guardrails |

## Acceptance criteria
1. WHEN `python -m emporio eval` runs with a valid key THEN it SHALL execute all scenarios and
   write `eval/results.md` with pass/fail per check, tools called, latency and tokens.
2. WHEN the final submission is made THEN ≥ 17 of 19 scenarios SHALL pass and every failure
   SHALL be explained in README §Limitations.
3. WHEN the examples script runs THEN it SHALL write 5 Markdown files to `examples/`.
